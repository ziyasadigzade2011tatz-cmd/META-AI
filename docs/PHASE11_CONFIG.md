# Настройки памяти и поиска

Базовые файлы: `studio/core/config/memory.json`, `search.json`, `search_domains.json`.
В установленной META они находятся в `_internal/core/config`.
Локальные переопределения читаются из `%LOCALAPPDATA%\META\core_config`;
неизвестные ключи игнорируются. Ключи API сюда не добавлять.
Общая диагностика выключена; `/debug on` включает её только для текущего чата.
Все оценки ниже — коэффициенты поиска, не вероятности истинности.

## memory.json

| Поле | Назначение |
|---|---|
| embeddings_enabled | Локальные векторы. При false остаётся лексический отбор |
| model | Уже установленная модель эмбеддингов; автоматического скачивания нет |
| embedding_timeout | Таймаут одного HTTP-запроса, ограничен 1–30 с |
| embedding_batch | Размер пакета, ограничен 1–32 |
| memory_gate_threshold | Порог смешанной оценки при доступном векторе, сейчас 0,50 |
| lexical_gate_threshold | Отдельный строгий порог запасного лексического пути, 0,72 |
| cosine_weight / lexical_weight | Веса смешанной оценки 0,8 / 0,2, нормируются суммой |
| semantic_only_threshold | Минимальный сырой косинус без общих слов, 0,64 |
| semantic_margin | Без общих слов выбирается только первый результат с отрывом от второго от 0,03 |
| top_k | Максимум записей, не более 5 |
| token_budget | Бюджет, не более 600 приблизительных токенов; оценка по длине / 3 |
| candidate_repeat_count | Число разных событий до подтверждения, минимум 2 |
| duplicate_threshold | Косинус для осторожного объединения дубликатов, 0,94 |
| background_interval | Интервал индексации, минимум 5 с |
| sensitive_categories | Категории, доступные только при личном прямом вопросе и пересечении слов |
| extract_enabled | Фоновое извлечение устойчивых фактов из новых сообщений |
| extract_retries | Число повторов занятого фонового разбора, не более 60 |
| extract_retry_seconds | Пауза повторов, 1–30 с; очередь не удерживает вычислительную блокировку |
| summary_enabled | Сохранение и поиск сводок |
| summary_threshold | Порог отбора сводок, сейчас 0,88 |
| summary_limit | Максимум сводок, 0–5 |
| summary_characters | Максимум символов одной подмешанной сводки, 100–3000 |

Порог 0,50 относится к смеси сырых косинусных и лексических оценок.
Он не ослабляет отдельный лексический запасной порог 0,72. Без общих слов дополнительно
обязательны минимум косинуса, первое место и отрыв. Эти значения подобраны на небольшом
синтетическом наборе: требуется независимая проверка новых формулировок.
Для максимально строгого режима можно поднять пороги; полнота станет ниже.

`/memory off` отключает новую запись, а не удаляет существующую память.
`/memory on` включает запись. `/memory candidates`, `/memory confirm id`,
`/memory forget текст`, `/memory export` управляют сохранёнными сведениями.
Удаление через forget затрагивает соответствующие производные векторы и историю изменений;
оно не стирает оригинальный чат или предварительную копию `.pre11`.

## search.json

| Поле | Назначение |
|---|---|
| domain_filter | Фильтр доменов; true по умолчанию |
| require_primary_for_official | Для явного требования официального источника отсекает неподтверждённые домены, включая кеш и редиректы |
| web_verify | Проверка предложений ответа по фрагментам; true по умолчанию |
| max_queries | Количество поисковых формулировок, 1–3 |
| max_sources | Размер отобранной выдачи, 1–10 |
| max_per_domain | Ограничение источников одного домена, максимум 2 |
| max_open_pages | Открываемые страницы, 1–6 |
| search_seconds | Общий мягкий бюджет: проверяется между сетевыми операциями |
| page_characters | Максимум используемого текста страницы, 1000–20000 |
| chunk_characters | Размер фрагмента, 200–2000, с перекрытием 150 символов |
| chunks_per_page | Выбранные фрагменты, 1–5 |
| semantic_weight | Вес косинуса в ранжировании выдачи |
| lexical_weight | Вес совпадений слов в ранжировании выдачи |
| reputation_weight | Бонус доменам из trusted |
| freshness_weight | Бонус текущему году, только если дата есть в результатах поиска |
| ttl_current | Срок кеша актуальных запросов, сейчас 300 с |
| ttl_general | Срок общего кеша, сейчас 86400 с |
| cache_max_mb | Ограничение кеша, 8–1024 МиБ, по умолчанию 128 |
| verify_timeout | Таймаут локального проверяющего запроса, 5–60 с |
| max_claims | Максимум предложений на проверку, 1–40; остаток не показывается |

Существующий сетевой загрузчик дополнительно ограничивает размер загрузки,
таймаут соединения/чтения и перенаправления и блокирует непубличные адреса.
Общий бюджет мягкий: начавшийся сетевой запрос может закончиться позже этого срока.

При `web_verify=true` черновик не транслируется пользователю до проверки.
Утверждения без допустимой точной цитаты из открытого фрагмента исключаются;
при недоступности проверяющей модели возвращается сообщение об отсутствии подтверждения.
Наличие точной цитаты проверяет код; логическое следование оценивает локальная модель,
которая может ошибаться. Это дополнительный фильтр, не гарантия достоверности.
При выключении web_verify сохраняется фильтр ссылок, но проверки утверждений нет.

## search_domains.json и диагностика

`blocked` — исключаемые домены, `allowed` — явные исключения пользователя,
`trusted` — группы доменов с бонусом репутации. Это начальный список, не полный каталог спама.
Социальный источник может пройти, если пользователь явно назвал этот сервис/домен в запросе.
`/domains block example.org` и `/domains allow example.org` меняют локальные правила.

`/debug on` показывает оценки памяти и причины отказа, выбранные сводки,
домены, фрагменты и результаты проверки утверждений. `/debug off` выключает вывод.
Сообщения, распознанные как личные, скрывают подробную диагностику.

## Скорость

Патч из `docs/CHAT_SPEED.md` сохранён. Фоновый разбор использует его `keep_alive`.
Эмбеддинги выполняются на CPU под общей блокировкой с генерацией; другая тяжёлая
модель ради индексации не выгружается. Занятая очередь означает пропуск с поздним повтором.
Если эмбеддинг ещё не вычислен, используется лексический путь.
При наличии векторов вычисление нового запроса может добавить задержку до HTTP-таймаута;
обычные приветствия не запускают такой поиск памяти.
