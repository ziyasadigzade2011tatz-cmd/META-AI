## Последние исправления META Code

### 1 Раннее прерывание запрещённой перезаписи

Наблюдавшаяся задача работала более двух часов с возобновлениями. Три попытки по 900 секунд генерировали index.html, после чего инструмент отклонял запись: существующий файл прочитан не полностью. В момент диагностики количество сохранённых изменений было нулевым, хотя потоковый текст рос. Повторяющаяся надпись «Готовлю index.html» была сигналом активности, а не свидетельством сохранения результата.

В studio/core/meta_studio/agent.py добавлен ReadBeforeWrite. Обработчик generation_event проверяет действие write уже при появлении имени файла в потоке. Если файл существует и не прочитан полностью, генерация тела прекращается, агент получает действие read. Это сохраняет запрет записи вслепую, а не отключает его.

Добавлен read_coverage: отпечаток содержимого и граница непрерывно прочитанных строк. Чтение выполняется порциями до 300 строк. Полное чтение отмечается только при реальном покрытии файла; обрезанный по лимиту фрагмент не считается полным. Повтор автоматического чтения того же участка без продвижения останавливается с объяснением.

Добавлен failure_counts по типу действия, пути и ошибке. После двух одинаковых ошибок повторы приостанавливаются, даже если модель каждый раз генерирует разный текст. Ранее различающиеся тела write обходили защиту по точному совпадению действия.

Системная инструкция теперь рекомендует edit для существующего проекта. Ограничения путей, проверка исходного SHA перед применением и запрет перезаписи непрочитанного файла сохранены.

Коммит: 9dc4491. Правка внесена напрямую в установленный agent.py. По просьбе пользователя тесты и резервные копии не создавались.

### 2 Поиск больше не подменяет создание программы

Следующая задача отправила в поиск начало технического задания: HTML, charset, viewport, title и другие требования. Когда относящиеся страницы не нашлись, исключение research завершило задачу ещё до написания кода.

В studio/core/meta5/task_brief.py изменён reference_query. При наличии распознанного референса используется он; при явной ссылке используется ссылка. Для сайта без конкретного референса используется справочный запрос HTML/CSS/JavaScript по MDN. Для прочих задач без объекта поиска возвращается пустой запрос. Полный текст технического задания больше не используется как запасной поисковый запрос.

В agent.py начальный поиск обёрнут обработкой ValueError, OSError и TimeoutError. Сохраняются web_attempted и research_unavailable, чтобы после возобновления не начинать тот же обязательный поиск заново. При недоступности источников агент получает указание продолжить код по требованиям и честно отметить отсутствие подтверждения референса.

Условие finish допускает такой явно отмеченный неуспех поиска. Итоговая сводка в этой ветке задаётся программно: изменения подготовлены по заданию, источники недоступны, сходство с референсом не подтверждено. Это не исправляет доступность самого поискового провайдера и не доказывает визуальное качество сайта.

Коммит: 8eebe3a. Оба файла перенесены прямо в рабочий Core. Новые тесты не запускались.

### 3 Завершение после проверки и защита готового черновика

Следующий журнал показал: index.html завершён, агент вызвал finish до check, получил требование проверки, выполнил успешный check, но затем продолжил чтение и начал write заново. В сохранённом журнале был готовый вариант на 17 124 символа; новое write заменило текущий черновик порцией на 613 символов.

В agent.py добавлены finish_target и finish_description. Когда агент просит закончить, но проверка ещё нужна, сохраняется отпечаток текущего набора изменений и намерение завершить. Если последующий check проходит, незавершённых файлов нет и отпечаток не изменился, finalize переводит задачу в review без дополнительного вызова модели. Для нового проекта сохраняется прежнее автоматическое применение после завершения; для существующего требуется применение пользователем.

Любая новая запись или правка сбрасывает прежнее намерение завершить. Успешная промежуточная проверка без предшествующего finish сама по себе не завершает задачу.

Повторный write для уже подготовленного законченного черновика запрещён. В потоке он прерывается рано; агент направляется к чтению, конкретной правке edit либо завершению. Центральная проверка write также содержит этот запрет. Первая замена старого файла после чтения и продолжение незавершённой порции через append остаются возможны.

Из существующих событий file и check вручную восстановлен ранее законченный index.html на 17 124 символа. Взята версия, для которой в журнале уже был успешный check. Задача переведена в review, applied=false, incomplete_files очищен. Новых проверок восстановленного сайта не запускалось. Это восстановление черновика из уже существующего журнала, не создание резервного архива. Сам файл проекта автоматически не применялся: пользователю предложено «Посмотреть изменения» и «Применить изменения».

Коммит: 09df55f. Рабочий агент заменён напрямую, приложение перезапущено. Тесты не запускались по требованию пользователя.

### На что распространяются исправления

Это изменения общей логики META Code для последующих задач, а не специальные подстановки для index.html, styles.css или сайта Meta. Имена этих файлов фигурировали в конкретной диагностике и восстановлении. Запрет повторного write и автоматическое завершение действуют по состоянию файлов и задачи.

Это не гарантия отсутствия любых циклов. Модель может выбирать лишнее чтение, делать неудачные edit, неверно трактовать требования или преждевременно просить finish. Без новых тестов последние исправления нельзя объявлять полностью проверенными.

### Последний известный журнал пользователя

Утверждать, что эта новая задача закончилась успешно, нельзя.

## 1. Что такое META

META — локальный Windows-ассистент с чатом, рабочим пространством разработки,
памятью, материалами и подключением к Ollama. Приложение запускает собственный
локальный Core и показывает веб-интерфейс внутри настольного окна.

Нужно различать три вещи:

1. **Приложение META**: интерфейс, запросы, файлы, разрешения, память и установка.
2. **Модель**: Qwen или другая установленная модель, которая генерирует ответ.
3. **Ollama**: отдельный локальный сервер, который загружает и исполняет модель.

Изменение языка интерфейса не добавляет модели знаний. Импорт памяти не меняет
веса нейросети. Чтение собственного исходника не означает автоматической замены
работающего приложения. Эти границы принципиальны для понимания результата.

## 3. Что изменено в 5.4.0

Основной вход интерфейса перенесён из `src.js` в `src.ts`. Добавлены контракты
TypeScript и новая панель инструментов. Сборка выполняет проверку TypeScript перед
Vite. При этом типизация переходная: в старых частях есть `any`, конфигурация не
полностью strict, а `activity.js` пока остаётся JavaScript. Это реальный этап
миграции, но не переписывание абсолютно каждой строки.

Python Core сохранён. Для окон добавлен отдельный C# / Win32 EXE. Настольная
оболочка использует существующий Qt/PySide-зависимый runtime. Вычисления модели
остаются в Ollama. Нового собственного C++-движка нейросети не написано.

PyTorch и TensorRT не подключены в рабочий путь. Для их использования понадобились
бы отдельный backend, совместимые веса/преобразования и измерения памяти и скорости.
Текущую работающую интеграцию Ollama на непроверенную интеграцию не заменяли.

Полный внутренний стек ChatGPT из использованной [официальной документации
Windows-приложения](https://learn.chatgpt.com/docs/app/windows) установить нельзя.
Поэтому META нельзя честно называть копией технологии OpenAI.

## 4. Технологическая схема

```text
Пользователь
    │
TypeScript/JavaScript + HTML/CSS + Monaco
    │ локальный HTTP, профиль и проверка Origin
Desktop HTTP-сервер
    ├── Python Core ── Ollama ── выбранная модель
    ├── SQLite: чаты, память, словарь, материалы
    ├── META Code: черновики → проверки → применение
    ├── C# / Win32: выбранное окно, только после подтверждения
    └── Исходники META → отдельный Git-проект → предложения изменений
```

| Часть | Технология и фактическая роль |
|---|---|
| Основная логика | Python; обработка сообщений, агенты, память, поиск, API. |
| API Core | FastAPI и Uvicorn в локальном процессе. |
| HTTP-клиенты | httpx и стандартные локальные HTTP-вызовы. |
| Интерфейс | TypeScript, оставшийся JavaScript, HTML и CSS. |
| Сборка UI | Vite; установленный TypeScript 7.0.2. |
| Редактор | Monaco Editor. |
| Настольное окно | Существующий Qt/PySide runtime с нативными библиотеками. |
| Модели | Отдельная Ollama, обращения к `127.0.0.1:11434`. |
| Работа с окнами | C# EXE, P/Invoke Win32, PrintWindow, System.Drawing. |
| Данные | SQLite и JSON, по назначению конкретного модуля. |
| Установщик | C#, встроенный ZIP-пакет и проверка SHA-256. |
| Страховка исходников | Git; без переноса личных данных в репозиторий. |

Сохраняется совместимый бинарный bootstrap `desktop_base.bin`. Его использование
означает, что полная замена старой оболочки чистым новым исходным проектом ещё не
завершена. Этот файл не является весами модели.

| `%LOCALAPPDATA%\META Next Preview` | Существует; защищённые старые данные не переносились и не очищались. |
| `C:\Users\Desktop\meta ver\META` | При проверке отсутствовал. |
| `Downloads\META_1_3_Hotfix` | При проверке отсутствовал. |
| `Documents\ChatGPT\META\META_Collected` | При проверке отсутствовал. |

Наличие `D:\META\Core` не доказывает, что именно он отвечает текущему окну.
Проверяемая установка запускает встроенный Core через свой EXE. Удалять другие
деревья или `.venv` на основании этого отчёта не предлагается: зависимости других
способов запуска здесь полностью не переисследовались.

## 7. Как выглядит интерфейс

Слева расположена боковая панель с брендом META, кнопкой нового разговора,
разделами приложения, списком разговоров и выбором профиля. Панель сворачивается.
Сверху основного пространства — название раздела, версия семейства, выбор модели
и справка. Конкретная тема зависит от сохранённых настроек пользователя.

По умолчанию используется спокойная тёмная палитра с акцентом. Настраиваются
основной фон и акцент, есть готовые варианты оформления, светлый/тёмный режим и
настройка движения. Пользовательские цвета не должны сбрасываться при обновлении.

Основные разделы:

- **META Chat** — разговоры, приветствие по времени суток, поле ввода и вложения.
- **META Code** — проекты, дерево файлов, Monaco, задача агента и проверки.
- **Проекты и задачи** — список проектов и сохранённых сессий разработки.
- **Материалы** — источники для поиска подходящих отрывков, не обучение весов.
- **Инструменты** — новая панель импорта памяти, окон/экрана и собственных исходников.
- **Персонализация** — внешний вид, профиль, роли моделей и параметры.

## 8. META Chat

Сообщения показываются в центральной области. Внизу находится редактор текста,
кнопка отправки и добавление файлов. Поддерживается отправка изображения; документы
могут извлекаться в текст и передаваться как материалы текущего запроса.

Панель «Действия» показывает этапы подготовки, выбранную модель, поиск и другие
события. Её можно свернуть, закрыть и открыть снова. Остановка связана с активным
сеансом Core, а не только с исчезновением текста в интерфейсе.

Часть запросов создания кода перенаправляется из чата в META Code. Запросы импорта
памяти или просмотра окна могут открывать нужный раздел инструментов. Это не
универсальная система распознавания любого намерения: детерминированные правила
маршрутизации имеют ограничения.

## 9. META Code

Рабочее пространство включает выбор проекта, список файлов, вкладки редактора,
поле задачи, выбор модели, прикрепление изображения, ленту действий и проверки.
Размеры панелей меняются перетаскиванием; режим фокуса увеличивает область кода.

Агент работает с реальными относительными путями выбранного проекта. Новый проект
создаётся в отдельной папке. Вначале изменения накапливаются в черновиках. Для
существующего проекта готовые изменения требуют применения; для нового проекта
успешно завершённый набор может применяться автоматически.

Основные действия агента: список файлов, чтение, поиск по проекту, план, запись,
точная правка, продолжение файла, статическая проверка, веб-поиск, уточнение,
локальная языковая справка и чтение собственных исходников.

Код из потока показывается как черновик. Видимый текст ещё не означает, что файл
проверен, применён или что приложение запускалось. Синтаксическая проверка также
не доказывает правильность алгоритма и визуальное качество.

## 10. Почему раньше казалось, что агент ничего не делает

В исследованной задаче на Qwen 9B агент не успел закончить JSON-действие записи за
300 секунд. Следовали два повтора. В последней попытке было 4262 символа, но
законченного действия и готового файла не получилось. Незавершённый результат
отбрасывался, поэтому ожидание не превращалось в сохранённый код.

Были и независимые проблемы интерфейса: полная перерисовка панели, сброс прокрутки
и секундомер, зависящий от прихода статуса. Поэтому долгий запрос мог выглядеть
как замёрзший экран. Продолжительность сама по себе не доказывает глубокое мышление
или улучшение дизайна.

Исправлены сохранение фрагментов, продолжение, увеличение размера ответа по
необходимости, независимый таймер и последовательный опрос. При потере связи
показывается проблема соединения; задача не запускается заново только из-за
повторного запроса статуса.

Локальные переопределения могут менять бюджеты в предусмотренных пределах.
Требование писать файлы «до 60 строк» удалено. Размер проекта не приравнивается
к выходу одного вызова модели: большой файл может продолжаться несколькими порциями.

В обычном диалоге существовал предел до 2000 выходных токенов; в этой миграции его
не увеличивали и не уменьшали. Контекст и выход — разные параметры. Контекст
включает инструкции, историю и файлы; выход — вновь сгенерированный текст.

У локальной Ollama нет расходуемого баланса API-токенов как у платного облачного
аккаунта. Однако память, скорость, контекст и предохранители приложения конечны.
«Бесплатно локально» не означает мгновенно или без ограничений железа.

ограничиваются общей локальной очередью между процессами META.

## 13. Понимание речи и контекста

Существуют детерминированный нормализатор и дополнительный локальный разбор JSON.
Обрабатываются известные сокращения, часть опечаток, раскладка, транслит,
растянутые слова и варианты сленга. Исходный смысл не должен автоматически
подменяться одной тематикой или увлечением пользователя.

Контекст формируется из текущего разговора, сводок и релевантной памяти. Есть
разрешение отсылок и построение самостоятельного вопроса для поиска. При
неустранимой неоднозначности предусмотрен уточняющий вопрос.

Это не полноценное человеческое понимание языка. Лексические правила, простая
морфологическая эвристика и небольшая модель могут ошибаться. Результат 120/120
на офлайн-наборе означает прохождение этого набора, а не безошибочность в любой
живой беседе и не равенство Claude/ChatGPT.

## 14. Память и «самообучение»

В проекте несколько разных механизмов, которые не следует смешивать:

- история сообщений — сохранённый разговор;
- факты и предпочтения — отдельные записи пользователя;
- сводка — сокращённый контекст конкретного чата;
- векторный индекс — поиск похожего смысла;
- словарь сленга — известные значения и пользовательские подтверждения;
- материалы — документы и источники, из которых подбираются отрывки.

Веса Qwen от этого не переобучаются. META получает подходящие сведения в контекст.
Она может запомнить неверно подтверждённый факт, поэтому память должна быть
просматриваемой и управляемой.

В памяти есть подтверждённые записи и кандидаты, источник, уверенность, срок и
история изменений. Релевантность ограничивает подмешивание фактов: хобби не должно
становиться темой любого вопроса. Предусмотрены локальные эмбеддинги и лексическая
запасная оценка. Наличие модуля не гарантирует, что каждый ответ использовал векторы.

## 15. Импорт памяти из других ИИ

Новая последовательность: выбрать экспорт или вставить текст → получить локальный
предпросмотр → отметить отдельные записи → подтвердить → добавить в SQLite.

Поддерживаются TXT/MD, списки `memories`, `saved_memories`, `facts`, известные формы
JSON-истории ChatGPT и Claude, а также ZIP с подходящим JSON. Для истории берутся
пользовательские реплики, а не заявления ассистента о пользователе.

Секреты, часть личных реквизитов и явные служебные инструкции исключаются.
Дубликаты не перезаписывают старые записи. Добавление выбранного набора выполняется
транзакцией. Подтверждённый предпросмотр используется один раз и имеет срок действия.

В интерфейсе ограничение файла — 3 МБ; на backend — 5 МБ и отдельная проверка
размера распакованного JSON. Показываются до 300 подходящих записей. Это не
универсальный импорт любых будущих форматов всех сервисов. Для большого экспорта
лучше подготовить отдельный список важных фактов.

Оригинальный файл не становится системной инструкцией и не даёт ИИ новых прав.
Реальная личная память пользователя в этой работе не импортировалась: проверки
выполнялись на синтетических данных.

## 16. Интернет и материалы

Поиск включает построение запроса из текущего контекста, несколько запросов,
ранжирование результатов, политику доменов, чтение страниц и проверку поддержки
утверждений по прочитанным фрагментам. Ссылки и источники должны быть наблюдаемыми.

Есть сценарии отсутствия результатов и тайм-аутов: нельзя выдавать выдуманный
источник за прочитанный. Для свежих фактов также важны дата и системное время.
Однако полная достоверность ответа не гарантируется: страницы могут быть неполными,
а модель может неверно связать факт и источник.

«Материалы» — это библиотека извлечённого текста, а не обучение нейросети на всех
документах. Добавление документа не доказывает, что каждый его абзац был использован
в ответе. В выпуске 5.4.0 реальный сетевой поиск по каждому сценарию заново не
прогонялся; основная новая проверка касается импорта, интерфейса и локальных функций.

## 17. Фотографии, экран и окна

Изображения читает отдельная vision-модель. Ей передаются пиксели и вопрос;
распознавание текста и мелких элементов может ошибаться. Не существует обещания
прочитать то, чего не видно на изображении.

Новая панель окон работает так:

1. Пользователь запрашивает список открытых окон.
2. Выбирает окно и действие: активация либо снимок.
3. Видит отдельное подтверждение именно этого действия.
4. Сервер проверяет одноразовое разрешение и неизменность выбранного окна.
5. Снимок сначала показывается в предпросмотре.
6. Только отдельная отправка передаёт снимок локальной vision-модели.

Доступ не является постоянным наблюдением. Разрешение действует 60 секунд и
не должно переиспользоваться для другого окна. Для запуска приложения вводится
полный путь к локальному EXE без произвольных аргументов.

Windows может запрещать активацию и захват. Минимизированное окно сначала нужно
развернуть. Защищённые окна и менеджеры паролей не должны обрабатываться этим
потоком. Пустое изображение не объявляется успешным чтением. Нельзя честно обещать
работу с абсолютно любым окном, DRM-поверхностью или повышенными правами.

Новая панель не является универсальным автономным управлением мышью и клавиатурой.
В старом реестре инструментов есть отдельный opt-in инструмент computer, но это
не означает, что он автоматически разрешён текущему чату.

## 18. Чтение и изменение собственного кода

`SelfSource` возвращает реальный список доступных исходников и выдержку с номерами
строк и SHA-256. Список исключает пользовательские базы, ключи, окружения, модели
и неподходящие файлы. Модель не получает доказательства чтения всего проекта только
из-за ответа «да, могу».

Для разработки создаётся отдельный Git-проект с исходниками и публичными настройками.
Это редактируемая рабочая копия, а не перенос живой установки. Изменения готовятся
через META Code; пользователь видит diff и разрешает проверки.

Тестовый runner дополнен так, чтобы при запуске проекта META использовались
модули изменяемой копии, а не уже импортированные модули установленного приложения.
Есть отдельная проверка идентичности пути исходника. Для замороженного Python
добавлена недостающая поддержка unittest, включая mock.

Автоматическая цепочка «любая правка → сборка → безопасная замена живого приложения
→ перезапуск → откат при проблеме» ещё не реализована целиком. Нельзя считать это
готовым автономным самообновлением. Сборка и установка остаются отдельными
проверяемыми действиями.

## 19. Языки программирования

Профили и локальные справки есть для Python, JavaScript, CSS, C# и C++.
Справка выбирается по задаче и файлам, а не целиком вставляется в каждый запрос.
Предусмотрен инструмент `language_help` с выбором раздела.

| Язык | Что проверяется автоматически | Чего проверка не доказывает |
|---|---|---|
| Python | AST и доступный разрешённый unittest. | Правильность всех алгоритмов, наличие любых зависимостей. |

| CSS | Структурные ошибки строк, комментариев и скобок. | Полную грамматику CSS, свойства, доступность и красоту. |

Наличие памятки C# не означает знания каждой версии любой библиотеки.

## 20. Разрешения и безопасность

Окно приложения и Core обслуживаются локально. Desktop проверяет профиль, Host и
Origin для своих маршрутов. Core использует отдельный локальный токен. Токены
не должны попадать в интерфейс, отчёты, исходники и установщик.

Файловые инструменты ограничены выбранным проектом; запрещены обход пути, ссылки
и неподдерживаемые цели. Существующие файлы должны читаться перед изменением.
Применение учитывает исходные хеши, чтобы не затереть стороннее изменение.

Разрешённый запуск тестов выполняется с правами пользователя и ограничениями
процессов/времени. Он не называется полноценной защитной песочницей. Чужой проект
может содержать опасный код: согласие на запуск тестов — содержательное решение.

Локальный пароль профиля не следует автоматически считать шифрованием всех SQLite.
Полный криптографический аудит хранения и авторизации в этой работе не проводился.
Ключи, личные данные и `.venv` не переносились в Git-проект саморазработки.

## 23. Проверки и смысл чисел

145 модульных тестов исходного проекта прошли после текущих исправлений.
120/120 офлайн-сценариев понимания речи проходили в предыдущем и новом сравнении.
Это отдельные наборы; их нельзя складывать и выдавать за процент качества модели.

В упакованном приложении проверяется полный набор из отдельной Git-копии и
дополнительный тест пути модуля. Первые прогоны обнаружили недостающий config,
unittest.mock и несовместимый способ запуска дочернего Python. Ошибки исправлялись,
а не объявлялись успехом. Итог окончательного прогона указан в завершающем разделе.

Реальная проверка агента 5.3.3 на Qwen 4B с искусственно малым выходом завершилась
за 190,2 секунды: два сохранённых фрагмента, два продолжения, два файла, ожидаемые
Python-функции без дубликатов. Она проверяла восстановление и синтаксис, не все
варианты поведения сгенерированной программы.

Нативный C#-захват и vision проверялись на созданном для этого окне, не на личных
окнах пользователя. Модель qwen2.5vl:3b распознала «42». UI-тесты подтверждают
отмену и отдельное одобрение действия, но не универсальное управление Windows.

## 24. Скорость и железо

Ориентир из запроса пользователя — 4 ГБ VRAM и 16 ГБ ОЗУ. Полный аппаратный аудит
повторно не проводился. Большая модель, контекст, подготовка запроса, чтение
изображения, поиск и повторные попытки имеют разные затраты времени.

9B может не помещаться целиком в видеопамять и работать существенно медленнее.
Длительное ожидание не означает лучшего результата. Маленькая модель может быть
быстрее, но переход на неё не гарантирует более точный код.

Обычные приветствия ранее измерялись отдельно: после подготовки модели повторный
короткий ответ занимал около 1–2 секунд, первый мог занимать заметно больше.
Это не гарантия такого времени для длинного вопроса, кода, поиска или фотографии.
Новая архитектура интерфейса сама по себе не ускоряет вычисления Qwen.

## 25. Чего нет или что остаётся слабым

1. Полная эквивалентность ChatGPT/Claude/Codex не доказана и не достигнута.
2. Веса модели не обучаются от каждого диалога; нет собственного полноценного обучения.
3. Нет подключённого генератора изображений.
4. Нет полного автономного самообновления с автоматической сборкой, установкой и откатом.
5. Не устранена вся совместимая архитектура: Core-агент и Desktop Sessions различаются.
6. Не вся старая оболочка представлена прозрачным новым исходным bootstrap.
7. TypeScript ещё не полностью строгий; часть UI остаётся динамической/JavaScript.
8. Нет обязательного браузерного испытания каждого сгенерированного сайта.
9. Нет доказательства компиляции произвольных C# и C++ проектов.
10. Нет гарантии поддержки любого защищённого окна и любого будущего формата экспорта.
11. Смысл, сленг, длинный контекст и утверждения модели могут интерпретироваться ошибочно.
12. Ограничены размеры задач и файлов; это локальный помощник, не бесконечная вычислительная система.

## Что учитывается

Считается весь окончательный текстовый промт: обязательная системная инструкция,
системные данные времени и темы, профиль, релевантная память, материалы,
веб-выдержки, история, текущий вопрос и служебное оформление Qwen.

Основной текстовый чат больше не использует 22 000 символов как главный бюджет,
когда новый блок включён. Релевантные сохранённые сводки продолжают добавляться
через существующий recall и входят в общий счёт. Прежний вызов compress в этой
ветке заменён токенным fit; при отключении блока возвращается прежнее поведение.

При переполнении сначала удаляются старые сообщения, затем уменьшаются или
исключаются дополнительные системные блоки. Сокращённые данные получают явную
пометку. Основная инструкция и последний вопрос не обрезаются. Если даже они
не помещаются, модель не вызывается: пользователь получает понятное сообщение
и существующее событие done с дополнительным признаком context_rejected.

Маршруты и поля запросов не менялись. Событие context_usage дополнено числами:
input_tokens, input_limit, output_limit, context_tokens, reserve_tokens,
input_percent, allocated_percent, count_method, exact, dropped_messages,
shortened_blocks и history_truncated. Старое поле estimated_characters сохранено
как диагностическое число символов отправляемых текстов, а не токенная оценка.

## Причина прежнего расхождения

Локальный счётчик ранее прогнозировал 19 токенов, а Ollama сообщала 23.
В фабрике renderer qwen3.5 установлен emitEmptyThinkOnNoThink=true. Поэтому даже
при think=false Ollama добавляет во вход `<think>\n\n</think>\n\n`. Локальная
реализация этот блок пропускала. Исправлено именно формирование промта, а не
добавлена произвольная константа «четыре».

Подсчёт читает словарь и BPE merges из GGUF установленной модели, не загружая
тензоры в GPU. Unicode-разбиение реализовано без новых библиотек. Метаданные
и часто встречающиеся части текста кэшируются в памяти процесса.

Форматирование проверено для текстового renderer qwen3.5 в Ollama 0.40.15.
При другой версии, недоступном GGUF или неподдерживаемом формате счётчик
не объявляет результат точным: для Qwen3.5 доступна консервативная верхняя граница
по UTF-8 байтам с запасом на оформление, exact=false. Она может сильнее сокращать
историю. Для прочих непроверенных моделей запрос с новым бюджетом отклоняется
с объяснением, а не получает выдуманный точный счёт. Слишком длинный единичный
фрагмент токенизации также приводит к понятному отказу, без бесконечного расчёта.

Источники алгоритма и форматирования:

- https://github.com/ollama/ollama/blob/v0.40.15/model/renderers/renderer.go
- https://github.com/ollama/ollama/blob/v0.40.15/model/renderers/qwen35.go
- https://github.com/ggml-org/llama.cpp/blob/master/src/llama-vocab.cpp
