не завершён. Установленное приложение, его данные, конфиги и установщик не менялись.
Показ рассуждений, агент кода, унификация контекста и сравнительные замеры не начаты.

Контрольная точка до работы: `a9b1f82`.

В исходниках подготовлены:

- `config/context_budget.json`: распределения 5500/2000 для чата, 4000/3500 для
  Thinking и 5000/3000 для будущего агента при контексте 8192, с пропорциональным
  масштабированием. `enabled=false`.
- `meta5/token_budget.py`: расчёт распределения и сокращение полного списка
  сообщений; слишком большой обязательный запрос отклоняется без обрезания.
  Подготовка заблокирована, пока новая возможность отключена.
- `meta5/qwen_tokens.py`: экспериментальный счётчик byte-BPE по словарю GGUF
  Qwen35 без загрузки весов в GPU и без новых зависимостей. Это ещё не проверенный
  точный счётчик полного запроса.
- `tests/test_token_budget.py`: тесты распределений, масштабирования и защиты.

Эти модули не подключены к `dialogue.py` или transport. Поведение чата не меняется.

Проверка на синтетическом англоязычном запросе с system «You are META.» и user
«Hello.» дала локальный прогноз 19 против `prompt_eval_count=23` в Ollama 0.40.15.
Ответ 4B завершился с `done_reason=stop`, `eval_count=10`, время 11,004 секунды.
Это проверка расхождения счётчика, не замер улучшения скорости. Содержимое
пользовательских чатов не использовалось. Попытка получить debug-render через API
не вернула debug_info: на этой установленной сборке нельзя полагаться на этот
флаг без дополнительной проверки.

Причина расхождения пока не установлена. Нужно сопоставить реальное форматирование
промта установленной Ollama с локальным renderer и проверить токенизацию на русском,
коде, Unicode и Thinking. До такой сверки нельзя заявлять точность или устанавливать
новый счётчик в рабочую META. Нельзя просто прибавить четыре токена по одному примеру.
