# Агент META: производительность, специалисты и GPU

## Установленные изменения

Рабочая база: `C:\Users\user\Documents\GitHub\META-AI`.
Основная модель выбирается пользователем: Qwen 3.5 4B, Qwen 3.5 9B либо Mimo V2.6 9B.
Веса моделей не менялись, дообучения не проводилось.

1. Обновления прогресса больше не читают/перезаписывают полный JSON задачи.
   Последний прогресс хранится в памяти и возвращается через существующие get/detail.
   После обычного события сохраняется контрольная точка с последним прогрессом.
   Черновики и законченные действия по-прежнему сохраняются на диск.
   При аварийном закрытии последнее значение таймера/превью может потеряться;
   незавершённая генерация не объявляется сохранённым готовым файлом.
2. Кэшируются неизменные сегменты токенизируемой истории: до 64 сегментов,
   суммарно до 256000 символов на токенизатор. Сегменты длиннее 20000 символов
   не кэшируются. Кэш защищён от одновременного доступа, результат подсчёта не меняется.
3. Финальная команда check может содержать complete=true и summary. Если код
   закончен и проверки успешны, отдельный запрос finish не нужен. Обычный check
   остаётся промежуточным; ошибки и незаконченные файлы не допускают завершение.
4. Архитектор и ревьюер доступны основному агенту через consult. Это отдельные
   ролевые запросы к той же выбранной локальной модели, без прав записи/исполнения.
   Не более двух консультаций на запуск, до 45 секунд и 600 выходных токенов каждая.
   Основной агент решает, когда они нужны; для простой задачи они не обязательны.
   Помощники видят до 6000 символов выдержек черновиков, а не весь проект.
5. Два детерминированных агента проверки — syntax и integration — работают
   параллельно, когда присутствуют обе группы файлов. Первый проверяет синтаксис,
   второй HTML и связи файлов/соответствие имеющемуся brief. Это проверки кода,
   а не два дополнительных LLM-вызова. Одновременно максимум два потока проверки.

## Схема работы

Задача → основной агент/план → при необходимости архитектор или ревьюер
→ запись/точные изменения → параллельные проверки → завершение.

Право изменять проект остаётся у основного агента: помощники не конфликтуют
из-за одновременной записи одного файла. Запросы к нейросети проходят через
общую вычислительную очередь. Одновременная загрузка нескольких тяжёлых моделей не используется.
Новые консультации и проверки видны в существующей панели действий.

## GPU и Ollama

Найдена NVIDIA GeForce RTX 3050 Laptop GPU, 4096 МиБ.
До изменений GPU уже использовался: у Qwen 4B size_vram около 1,88 млрд байт,
у Qwen 9B и Mimo — 1,68 млрд. Загруженная 9B занимала около 6,40 млрд байт
в сумме по полю size. Это показатели Ollama, а не измерение загрузки всех ядер CPU.
Полностью разместить такую модель в 4 ГБ VRAM нельзя. CPU остаётся частью вычислений.

Для текущего пользователя Windows установлены:

- OLLAMA_FLASH_ATTENTION=1
- OLLAMA_NUM_PARALLEL=1
- OLLAMA_MAX_LOADED_MODELS=1

Ollama перезапущена с этими настройками. Распределение слоёв между CPU/GPU оставлено
автоматическому планировщику; принудительная загрузка всех слоёв не вводилась.
Эксперимент с OLLAMA_KV_CACHE_TYPE=q8_0 не дал убедительного выигрыша Mimo,
поэтому эта переменная восстановлена в прежнее значение. Точность KV-кэша специально не снижена.
Скрипт повторной настройки: studio/build_tools/configure_ollama_performance.ps1.

Основание настроек: [официальная документация Ollama](https://github.com/ollama/ollama/blob/main/docs/faq.mdx).
Настройки Flash Attention/KV-кэша не являются гарантией ускорения любой модели.

## Измерения

Микротест: 15 повторных подсчётов одной истории из 20 сообщений после прогрева:
до кэша 0,209628 с, после 0,001635 с. Это ускорение счётчика, не всей генерации.
Тест 1000 обновлений прогресса: 0 полных записей сессии; следующее событие создаёт
1 контрольную точку. До изменения каждая такая запись вызывала atomic_json/fsync.

Короткий запрос list, окно 8192. По два вызова каждой модели; таблица показывает
скорость генерации второго, прогретого вызова. Замеров мало, температура ненулевая,
число выходных токенов иногда различается. Это не контролируемое доказательство ускорения.

| Модель | До, токенов/с | Эксперимент с q8_0, токенов/с |
|---|---:|---:|
| Qwen 3.5 4B | 11,86 | 13,09 |
| Qwen 3.5 9B | 5,11 | 6,27 |
| Mimo V2.6 9B | 5,01 | 4,92 |

Столбец эксперимента НЕ является результатом окончательных настроек: q8_0 отменён.
Первичная загрузка занимала примерно 8–14 секунд. Повторный вызов загруженной
модели почти не тратил время на загрузку. Консультации поэтому сохраняют ту же модель.

Реальная ограниченная задача Mimo: создание settings.json, 4 действия, 65,368 с,
статус completed, JSON соответствует заданным полям, проверка syntax успешна.
Это простой файл, не оценка качества сайта. Отдельная проверка установленного Core:
/health online, Ollama connected, короткий чат ответил; Desktop-чаты не создавались.
Этот чат пересёкся с проверочным агентом в общей очереди и не используется для сравнения скорости.

Автотесты проверяют очередь, бюджеты, параллельность двух проверок, консультацию
без прав записи, прогресс без частого fsync и финальный check без лишнего finish.
Окончательный результат: 169 тестов, все успешны, 14,711 секунды;
все 160 Python-файлов studio компилируются. Журнал: local/maintenance/team-tests.txt.

## Применение и ограничения

Изменения скопированы в local/app/_internal/core; работающие окна META не прерывались.
После завершения текущих задач выйдите из META через трей и откройте её снова.
Настройки Ollama уже действуют. Установщик и GitHub-релиз не обновлялись.

Более высокое качество сложных проектов и кратное ускорение Mimo не доказаны.
Новые проверки не заменяют тесты приложения и визуальную проверку сайта.
Автономных параллельных кодеров с независимыми правами записи здесь нет:
один исполнитель, консультанты и параллельные проверяющие — намеренная граница.

Checkpoint до изменений: ab72031. Откат исходников — git revert коммита обновления
с последующей синхронизацией затронутых файлов в local/app/_internal/core и перезапуском.
Прежние значения только четырёх затронутых переменных Ollama сохранены локально
в local/maintenance/ollama-tuning-previous.json; для их восстановления используйте
[Environment]::SetEnvironmentVariable(имя, прежнееЗначение, 'User') и перезапустите Ollama.
Этот файл не содержит ключей API и не включён в Git.
