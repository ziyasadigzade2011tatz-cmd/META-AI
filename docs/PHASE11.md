# Фаза 11 — память по смыслу и проверяемый поиск

Состояние на 5 ноября 2026 года. Изменены исходники и Core существующей установки
`C:\Users\Desktop\META_FULL_DESKTOP\META-Next`. Версия EXE/интерфейса остаётся 5.3.
Публичный установщик v5.3.0 этой фазой не пересобирался и не публиковался.
Скоростной патч `5574e62` сохранён: обычный чат Qwen 4B, без Thinking,
удержание модели 900 секунд, быстрый путь отдельных приветствий.

## Что действительно реализовано

1. Локальная embeddinggemma через официальный `POST /api/embed`, пакетная обработка,
   BLOB float32, размерность и digest модели, кеш и переиндексация изменённых записей.
   [Документация эндпоинта](https://docs.ollama.com/api/embed).
2. Добавляющая миграция SQLite с копией через backup API рядом: `memory.sqlite.pre11`.
   Исходные столбцы фактов и тексты сохраняются; схема не заменяется.
3. Гибридный отбор памяти, отдельные правила хобби/имени/языка/железа/чувствительных
   категорий, максимум 5 записей и приблизительно 600 токенов.
4. Фоновое локальное извлечение точных пользовательских цитат о себе. Кандидат,
   повтор разных событий или явное подтверждение. История явных изменений,
   осторожная проверка смысловых дубликатов, команды `/memory`.
5. Извлекающие сводки каждые 6 реплик; по умолчанию только текущий чат.
   Чужие чаты допускаются только при явной просьбе вспомнить прошлые обсуждения.
6. До 3 поисковых запросов фазы 10, RRF, дедупликация, политика доменов,
   смысл/слова/репутация/доступная дата, максимум 2 результата одного домена.
7. Чтение ограниченных страниц, фрагменты, локальные векторы кеша, TTL,
   суточная очистка производного кеша и ограничение его размера.
8. Черновик веб-ответа удерживается до проверки отдельных предложений.
   Проверяющая модель возвращает строгие вердикты и цитаты; код проверяет,
   что цитата действительно есть в открытом фрагменте. Неподтверждённое исключается.
   Ссылки допускаются только из открытых страниц, включая ссылки внутри блоков кода.
9. Диагностика выбора/отказа памяти, сводок, источников, фрагментов и проверки
   через `/debug on`; по умолчанию выключена.

## Конвейер

Исходный текст сохраняется оболочкой → нормализация и разрешение текущего контекста
фазы 10 → фильтр приватности → отбор подтверждённой памяти → при необходимости
поисковый план → фильтр и ранжирование выдачи → открытие страниц и фрагменты →
локальный черновик → проверка опоры и ссылок → ответ → фоновая запись кандидатов
и сводка на очередном интервале.

Веса модели не обучаются и не изменяются. «Обучение» здесь означает управляемое
сохранение фактов/словарных сведений и их последующий поиск. Это не дообучение Qwen.
Память и эмбеддинги не используют облачные провайдеры. Веб-поиск получает построенный
по текущему разговору запрос, а не базу памяти. Фильтры личных данных эвристические:
они не дают математической гарантии распознавания любого возможного секрета.

Проверенные настройки рабочей установки: Fast/чат и Understand — `qwen3.5:4b`,
Thinking и Code — `qwen3.5:9b`, Vision — `qwen2.5vl:3b`.
Thinking и глубокий поиск по умолчанию выключены скоростным патчем;
роли 9B не удалены и не запускаются одновременно с другой тяжёлой генерацией.
Выбор 4B для обычного чата опирается на замеры задержки из CHAT_SPEED.md,
а не на доказанное превосходство качества над другими моделями.

## Пороги и смысловой поиск

При доступных векторах:
`score = (0.8 × cosine + 0.2 × lexical) / (0.8 + 0.2)`.
Порог смеси 0,50. Запасной лексический путь имеет отдельный порог 0,72.
Без общих слов дополнительно нужны сырой cosine ≥0,64, первое место и отрыв ≥0,03.
Категорийные запреты применяются до оценки. Лексическая часть — нормированное
IDF-взвешенное пересечение слов, не полноценный морфологический BM25.

Первоначальные пороги дали 0/20 реальных перефразирований: их нельзя было оставить
и объявить смысловой поиск работающим. После калибровки получено 17/20.
Эта же выборка использовалась при настройке; независимого подтверждения обобщения нет.
Порог можно сделать строже, уменьшив полноту. Все поля описаны в
[PHASE11_CONFIG.md](PHASE11_CONFIG.md).

## Размер и скорость

Модель embeddinggemma уже имелась: 621875917 байт, digest
`85462619ee721b466c5927d109d4cb765861907d5417b9109caebc4e614679f1`.
20 синтетических записей: первичная индексация 5,813 с; пакет 20 запросов 4,732 с.
Повтор с кешем: 0,031 с и 0,004 с соответственно. Кешированный и первичный прогоны
нельзя сравнивать как ускорение самой модели.
20 векторов памяти занимают 61440 байт (768 float32 на запись),
40 кешированных векторов — 122880 байт; файл тестовой базы — 319488 байт
до дополнительных отрицательных запросов. Размер рабочей памяти без фактов — 73728 байт.
В ходе индексации Qwen 4B оставался загруженным до и после.

Эмбеддинги выполняются на CPU и сериализованы общей очередью с генерацией.
Фоновая запись не переключает модель, если загружена другая, и повторяется позже.
При постоянной занятости или закрытии приложения часть ещё не сохранённой очереди
может потеряться. Фоновая очередь ограничена 16 сообщениями и не пишет их текст на диск.

## Отключение и откат

1. Для отключения новых блоков используйте локальные настройки: `embeddings_enabled=false`,
   `extract_enabled=false`, `summary_enabled=false`. Для отключения проверки веб-ответа
   — `web_verify=false`; это уменьшает защиту. `/debug off` выключает диагностику.
   Сам интернет отключается существующей настройкой оболочки.
2. Для отката исходников используйте `git revert` нужных коммитов фазы 11 от новых
   к старым, сохраняя `5574e62`. Пересекающиеся изменения dialogue.py могут потребовать
   разрешения конфликта; нельзя заменять всю ветку на старый снимок с потерей ускорения.
3. Откат Git сам по себе не меняет установленную программу и пользовательские базы.
   Закройте META целиком перед возвратом Core. Старый Core с INSERT из 4 значений
   несовместим с добавленными столбцами, поэтому просто поставить старый memory.py нельзя.
4. Если действительно нужен возврат исходной схемы памяти, используйте подготовленную
   `.pre11` через backup API. Все сведения памяти, добавленные после копии, будут потеряны;
   оригинальная база чатов не затрагивается. Пример из корня репозитория:

```powershell
& 'D:\META\Core\.venv\Scripts\python.exe' -B studio/build_tools/restore_pre11_memory.py `
  'C:\Users\user\AppData\Local\META\core_state\memory.sqlite' `
  --confirm-loss-of-later-memory
```

Скрипт восстановления не запускается автоматически. Не восстанавливайте базу при
открытых процессах META. `.pre11` не добавляется в Git.

## Что осталось слабым

- Калибровка смысловых порогов на 20 примерах; нужен отдельный большой контрольный набор.
- Три перефразирования пропущены; словоформы — эвристические основы, без новой установки pymorphy.
- Устойчивые факты извлекаются консервативно точными цитатами; часть полезных формулировок теряется.
- Противоречия уверенно обрабатываются только для явных слотов и прямого отрицания предпочтения;
  общего надёжного логического анализа всех противоречий нет.
- Проверяющая модель может ошибиться в логическом следовании даже при настоящей цитате.
- Навигация страниц удаляется эвристически; некоторые страницы с реквизитами отклоняются целиком.
- Свежесть учитывается, только если поисковый результат содержит дату; полного извлечения дат нет.
- Начальный список доменов не исчерпывает спам и копипасту. Живая выдача не проверена.
- Веб-проверка добавляет локальный модельный вызов и задержку; простой чат её не использует.
- Публичный установщик и GitHub-релиз этой фазой не обновлены.
