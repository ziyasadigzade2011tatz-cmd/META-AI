# META-AI

Собрание исходников локальной Windows-системы META Core и Desktop, найденных на диске D, в «Загрузках» и рабочей папке этого чата. Снимок подготовлен 2 ноября 2026 года. Оригинальные файлы не перемещались и не изменялись.

## Структура

| Каталог | Содержимое |
| --- | --- |
| `installed_meta/Core` | Фактические исходники установленного Core, включая текущие `main.py`, `meta40` и веб-мост |
| `installed_meta/Projects` | Небольшие проекты и примеры из рабочей папки META |
| `installed_meta/Models` | Описания и манифесты моделей без весов |
| `desktop` | Исходники Desktop, интерфейс, ресурсы, небольшой запускатель и предыдущие копии кода |
| `downloads/META_4_4_Chat_Web` | Распакованное обновление веб-поиска обычного чата |
| `releases/meta40_upgrade` | Подготовленный в этом чате комплект обновления 4.0 с исправлением 4.0.1, тестами и инструкцией |
| `archives` | Архивы обновлений, содержимое которых проверено перед включением |
| `docs` | Подробный отчёт, его PDF-копия и вспомогательные исходники создания документа |
| `tools` | Скрипт сбора файлов |

`SOURCE_INDEX.json` содержит путь каждого собранного исходного файла, группу происхождения и SHA-256 копии. Одинаковые файлы разных выпусков сохранены в своих каталогах, чтобы не потерять структуру обновлений. Исторические `before`, `backup` и `.bak` — архив предыдущих вариантов, а не текущие точки входа приложения.

## Какая версия является текущей

Текущий срез установленной системы находится в `installed_meta/Core` и `desktop`. Он уже содержит дополнительные файлы `context.py`, `selfdev.py`, `web_tools.py`, `web_research.py` и `meta_web_bridge.py`, которых не было в исходной сборке 4.0 этого чата. В «Загрузках» найден комплект META 4.4 Chat Web. При этом константа версии пакета `meta40` может оставаться 4.0.1: один номер не описывает все установленные дополнения.

Каталог `releases/meta40_upgrade` — более ранний самостоятельный комплект обновления. Не копируй его поверх текущего Core для восстановления последних дополнений. Файл `main.py` из загрузочного пакета 4.4 является контрольным примером; используй его установщик и инструкцию, а не ручную замену текущего Core.

## Что намеренно не публикуется

- Живой `meta40_config.json` с токеном. Вместо него добавлен `meta40_config.example.json` с заглушкой.
- Личные чаты, профиль и учётная запись Desktop, базы памяти, журналы, изображения из пользовательских сообщений и история задач.
- Веса Ollama, виртуальное окружение Python и кэш. Веса моделей занимают около 22 ГБ и остаются на исходном диске.
- Служебные манифесты локального отката, содержащие привязку к конкретной установке. Архивные исходники сохранены, но это не заменяет оригинальное хранилище отката на компьютере.
- Посторонние установщики, игры и стандартные Java-каталоги `META-INF`, не связанные с проектом META.

Полная локальная опись включённых и исключённых файлов хранится рядом с собранием в `META_Collection_Inventory.local.json`. В репозиторий она не включается.

## Запуск и восстановление

Это собрание исходников, а не самодостаточный установщик Windows. Приложение использует фиксированные пути `D:\META\Core`, `D:\META\Projects` и локальные службы Core/Ollama. Базы пользовательских данных и Python-окружение здесь отсутствуют.

`requirements.local-snapshot.txt` фиксирует названия и версии 41 пакета из текущего окружения META. Он получен чтением метаданных пакетов, без запуска приложения. Исходный `Core/requirements.txt` на момент сбора пуст. Снимок зависимостей — справочная информация, не проверенная инструкция для чистой установки.

Перед восстановлением настрой отдельное Python-окружение, восстанови пути, создай новый локальный токен вместо заглушки в примере конфигурации и установи нужные модели Ollama. Действующее окружение и личные данные не следует заменять этим снимком. Инструкции прежних обновлений находятся в соответствующих каталогах.

Собранные текущие файлы не запускались и не применялись повторно при сборе. Ранее пройденные 17 проверок относятся к комплекту 4.0.1 из `releases`, а не доказывают исправность всех позднейших дополнений.

## Работа с GitHub

Рекомендуемый формат — закрытый репозиторий. В `.gitignore` добавлены правила для локальных токенов, баз, истории, моделей и окружений. Перед последующими коммитами сохраняй эти исключения и проверяй новые файлы. Не добавляй личные данные командой принудительного включения игнорируемых файлов.
