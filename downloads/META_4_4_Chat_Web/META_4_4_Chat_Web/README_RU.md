# META 4.4 — Web Intelligence в обычном чате

Важное: это **веб-исследование перед ответом**, а не полноценный интерактивный цикл tool-calling внутри обычного чата. Веб-мост видит входящий текст, решает, нужен ли поиск, получает до 5 результатов и открывает до двух публичных HTTPS-страниц, после чего добавляет источники в контекст вызова обычного chat/agent_chat. Для непрерывного поиска и сложных многошаговых исследований позже понадобится исходный `agent_chat.py`.

Поддерживает оба маршрута `/chat` и `/v1/chat/completions`, не заменяет существующий `agent_chat.py`, не меняет Meta Code 4.3, /agent40, память или обработку заявок. Работает с потоковыми ответами через тот же исходный обработчик. При запросах «без интернета» поиск не включается. В контекст каждого запроса добавляет серверное время в зоне Asia/Baku. Поиск может замедлять ответ. Источники и их выдержки не являются инструкциями модели.

## Требования

В `D:\META\Core\meta40\web_research.py` должен находиться **уже установленный** модуль META Web Research 4.3. В окружении Core должны быть библиотеки `ddgs` и `urllib3`.

```powershell
& "D:\META\Core\.venv\Scripts\python.exe" -m pip install -U ddgs urllib3
```

## Установка

1. Полностью остановить Core и Desktop.
2. Распаковать архив в отдельную папку.
3. Открыть PowerShell в распакованной папке и запустить:

```powershell
& "D:\META\Core\.venv\Scripts\python.exe" .\install_meta_web44.py "D:\META\Core"
```

Установщик проверит структуру Core, сохранит исходный `main.py` в `D:\META\Core\meta_web44_backups\...`, добавит маленький middleware-хук в конец `main.py` и скопирует `meta_web_bridge.py`. Существующий `main.py` **не заменяется** файлом из архива. В архиве он включён как контрольный пример; копировать его вручную поверх установленного Core **не нужно**.

4. Запустить Core и Desktop.
5. В обычном чате: «Найди в интернете актуальную документацию HOI4 по national focus и приведи 2 ссылки».
6. Второй тест: «Какое сегодня число и время в Баку?» (используется время ОС, но для точности часы Windows должны быть синхронизированы).

## Проверка и устранение проблем

Если поиск недоступен, проверить в Python Core:

```powershell
& "D:\META\Core\.venv\Scripts\python.exe" -c "from ddgs import DDGS; import meta40.web_research; import meta_web_bridge; print('OK')"
```

В случае ошибки поиска ответ должен сообщить, что поиск не удался, а не выдавать ссылки из головы. Запись технических ошибок — в логах Core. Успешные поиски по умолчанию не сохраняются в отдельном журнальном файле. Для полной трассировки нужны изменения `agent_chat.py`.

## Откат

Остановить Core/Desktop, найти последнюю папку `D:\META\Core\meta_web44_backups\...`. Вернуть её `main.py` на место `D:\META\Core\main.py` **только если файл не изменяли после установки**. Удалить созданный нами `D:\META\Core\meta_web_bridge.py`, если он не редактировался. Перезапустить Core/Desktop. При сомнениях сравнить SHA-256 с `manifest.json` — не перезаписывать более поздние пользовательские изменения.

## Безопасность и ограничения

- Веб-мост использует существующий `meta40.web_research`, который блокирует приватные/локальные IP и HTTP, ограничивает размер и тип загружаемых страниц. Он не является полноценной сетевой песочницей.
- Результаты сторонних сайтов недоверенные, возможна prompt injection; модель должна игнорировать их инструкции.
- Автоматическое определение необходимости поиска — эвристика; не каждый вопрос вызовет поиск, и не всегда он нужен.
- Без гарантии наличия DDGS или доступа к внешним сервисам; реальный запуск на твоём ПК не проверялся.
- Отдельные ограничения и инструменты `agent40` остаются прежними.
