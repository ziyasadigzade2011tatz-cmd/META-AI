# META 4.0 — устанавливаемое обновление

Исправление 4.0.1: панель умеет создавать новую папку проекта при запуске задачи. Для уже установленной 4.0 закрой Desktop и Core и запусти `python patch_meta401.py` через Python META. Повторная полная установка не нужна. Квитанция отката исправления сохраняется отдельно в `meta40_backups`.

Обновление для существующих `D:\META\Core` и `%USERPROFILE%\Downloads\META_1_3_Hotfix`.
Новый агент доступен отдельной кнопкой **«✦ Агент 4.0»** в Desktop. Старый чат продолжает использовать прежний маршрут.

## Установка

1. Распакуй архив целиком, например в `%USERPROFILE%\Downloads\META40`.
2. Закрой все окна META Desktop и останови процесс META Core, который занимает порт 8000. Ollama оставь включённой.
3. Запусти `Install_META_4.cmd` из распакованной папки. Он сначала проверяет совместимость, затем устанавливает обновление. Установщик использует уже существующий Python META; ничего не скачивает.
4. Запусти `%USERPROFILE%\Downloads\META_1_3_Hotfix\Start_META.cmd`. Этот запуск гарантированно использует обновлённые Python-файлы и ресурсы, а не ресурсы старой автономной EXE-сборки.
5. Войди в локальный профиль META. Если его нет, создай его в настройках. Открой **«✦ Агент 4.0»**. Выбери установленную модель Ollama, например `qwen2.5-coder:14b`.

Из PowerShell, находясь в распакованной папке:

```powershell
& 'D:\META\Core\.venv\Scripts\python.exe' .\install_meta40.py --check
& 'D:\META\Core\.venv\Scripts\python.exe' .\install_meta40.py
```

При других путях укажи `--core`, `--desktop` и `--projects`. Путь `--projects` должен совпадать с `WORKSPACE` существующего `agent_tools.py`. Основная папка Projects должна существовать; новую подпапку проекта можно создать из панели, включив «Создать папку проекта, если её нет». При несовместимых исходниках установщик останавливается до изменения файлов. Повторная полная установка поверх 4.0 блокируется: для исправления 4.0.1 используй `patch_meta401.py`.

## Первый видимый результат

В архиве есть маленький проект с намеренной ошибкой сложения и тестом. Скопируй его в рабочую папку:

```powershell
Copy-Item -LiteralPath .\examples\meta40_demo -Destination 'D:\META\Projects\meta40_demo' -Recurse
```

В панели агента:

- Проект: `meta40_demo`.
- Модель: `qwen2.5-coder:14b`.
- Шагов: `16`.
- Разреши Python unittest: этот пример содержит проверяемый исходный код из архива.
- Задача: **Прочитай calc.py и test_calc.py. Запусти тест, исправь функцию add, снова проверь тестом. Не меняй тест. Подготовь заявку.**

Журнал показывает выбор инструментов и результаты тестов. После завершения появится diff и кнопки применения / отклонения. До нажатия «Применить показанные изменения» исходные файлы проекта не меняются. Если модель исчерпала бюджет или не сформировала заявку, панель покажет это явно.

Для своего проекта укажи имя подпапки внутри `D:\META\Projects`, например `my_app`. Если папки ещё нет, оставь включённым «Создать папку проекта, если её нет». Это создаёт пустую папку при запуске; сгенерированные файлы по-прежнему требуют подтверждения заявки. Значение `.` означает всю папку Projects; для более точного контекста выбирай отдельный проект.

## Возможности

- Настоящий ограниченный цикл: модель выбирает чтение, поиск, правки и тесты, получает результат инструмента и решает следующий шаг.
- Ollama `/api/chat`, структурированный JSON-протокол, доступные модели из `/api/tags`. Обращения идут только на `127.0.0.1:11434`, без внешнего HTTP-прокси.
- Снимок проекта, буквальный поиск с номерами строк, чтение перед изменением существующего файла, отдельный слой правок.
- Python/JSON проверяются до включения в правки. Новые вложенные каталоги создаются только при подтверждении заявки.
- Одна многофайловая заявка в существующем `agent_pending`, совместимая с Desktop. Перед применением проверяются хэши исходных файлов. Ссылки, junction, абсолютные пути, выход за Projects, ADS и имена устройств Windows запрещены.
- Подтверждение целой заявки, журнал восстановления, резервное содержимое изменяемых файлов, попытка отката при ошибке записи.
- История задач и последние сведения по каждому проекту сохраняются между перезапусками. Прошлое резюме передаётся модели как недоверенные данные; статус `pending` ещё не означает, что правки применены.
- Фоновая задача, журнал действий, остановка, восстановление просмотра через историю. После перезапуска незавершённая задача помечается `interrupted`; сама не продолжается.
- Новые API защищены локальным токеном. Desktop передаёт его сервером; токен не попадает в JavaScript. Для новых действий нужны профиль, вход и проверка источника запроса.

## Запуск тестов: точные границы

По умолчанию исполнение выключено. Для каждой задачи нужно отдельно разрешить его в панели и подтвердить. Профиль только один: **python-unittest**; произвольных команд, shell, pip, npm и выбираемых моделью аргументов нет.

Код запускается в временной копии разрешённых UTF-8 файлов с текущими правками. Это **не изоляция Windows**: тестовый Python-код получает права пользователя, может обращаться к сети и файлам вне копии. Используй разрешение для доверенного проекта. Переменные окружения с ключами не передаются, но это не защищает от чтения данных самим кодом.

На Windows дочерние процессы помещаются в Job Object с завершением всего дерева, ограничением числа процессов и памяти. Пользовательский код начинает выполняться после подключения процесса к Job Object. Если подключение не получилось, тест не выполняется. Лимит одного запуска — 30 секунд; вывод — 32 КБ; до четырёх запусков тестов за задачу. Ноль найденных тестов считается неуспехом. Отмена во время обращения к Ollama может ожидать завершения текущего запроса до 60 секунд. Общий срок также может превышаться на время уже начатого сетевого запроса и подготовки снимка.

Снимок не включает `.git`, `.venv`, `node_modules`, скрытые файлы, двоичные данные и файлы больше 20 КБ. Тестам, требующим таких данных, внешних зависимостей или pytest, нужна отдельная настройка в будущей версии. В Python-тестах используются пакеты существующего Python META и доступные исходники снимка.

Лимиты задачи: 1–30 шагов, по умолчанию 10 минут; 12 изменённых файлов, 20 КБ каждый, 100 КБ вместе; снимок — до 1000 файлов / 8 МБ. Проверка Python/JSON — синтаксическая, не доказательство корректности. Несколько замен файлов не являются общей атомарной транзакцией: при отключении питания восстановление выполняется по журналу. Против одновременной злонамеренной подмены файлов другим локальным процессом OS-изоляции нет.

## Откат обновления

Останови Desktop и Core. Установщик печатает точный путь `Rollback manifest`. Запусти из папки обновления:

```powershell
& 'D:\META\Core\.venv\Scripts\python.exe' .\install_meta40.py --rollback 'D:\META\Core\meta40_backups\ДАТА_УСТАНОВКИ\manifest.json'
```

Подставь существующий путь, напечатанный установщиком. Откат восстанавливает прежние файлы и убирает добавленные программные файлы. Если после обновления их вручную редактировали, откат остановится, сохранив поздние изменения. Резервные копии, история `meta40_state`, журналы и созданные пользователем данные остаются. Старые чаты, Ollama, модели и базы установка не изменяет. Уже применённые изменения проектов откатываются отдельно.

## Откат изменений проекта

Каждое успешное применение сохраняет квитанцию в существующем `pending_changes\meta40_receipts\ID.json`. ID виден в истории задачи. В PowerShell:

```powershell
Set-Location 'D:\META\Core'
& '.\.venv\Scripts\python.exe' -m meta40.proposals rollback ID_ЗАЯВКИ
```

Замени ID на 32 шестнадцатеричных символа. Это явное локальное действие: содержимое старых файлов восстанавливается, новые файлы из заявки удаляются. Если позже файл изменён, восстановление блокируется до ручного разбора. Пустые каталоги могут остаться. При сбое между заменами файлов этот же инструмент восстанавливает состояние по квитанции `applying`. Не удаляй квитанции до завершения проверки. Откатывай проект до удаления пакета 4.0.

## Проверки и диагностика

```powershell
& 'D:\META\Core\.venv\Scripts\python.exe' -m unittest discover -s tests -v
& 'D:\META\Core\.venv\Scripts\python.exe' .\demo_ollama.py
```

`demo_ollama.py` запускает настоящую локальную модель на временном примере и сохраняет `LIVE_DEMO_RESULT.json`. Он разрешает выполнение только включённого маленького примера и не применяет правки к рабочему проекту. Модель может давать разные результаты; тест не является бенчмарком.

Статус и история: Core `/agent40/status`, `/agent40/models`, `/agent40/tasks`, `/agent40/tasks/{id}`, POST `/agent40/tasks`, POST `/agent40/tasks/{id}/cancel`. Нужен заголовок `X-Meta40-Token` из `meta40_config.json`; не публикуй этот файл. HTTP-маршрута применения файлов в Core нет. Desktop использует существующее локальное подтверждение `/api/proposals/{id}/apply`.

При ошибке смотри журнал панели, `meta40_state\ID.json` и старый Desktop `data\core.log`. Если кнопки нет — проверь, что запущен `Start_META.cmd`, а не старая автономная сборка, и что закрыт старый сервер на 8767. Если моделей нет — проверь, запущена ли Ollama. Если тесты не прошли — смотри фактический вывод, даже когда резюме модели утверждает обратное.

## Что пока не реализовано

Git/GitHub, произвольный терминал, браузер инструментов, npm/pytest, автоматическая установка зависимостей, LSP, удаление/переименование файлов и работа агентов параллельно. Текущая версия выполняет одну задачу за раз. Процент сходства с Claude Code не измерялся; качество программирования зависит от выбранной локальной модели. Изменения интерфейса проверены по синтаксису и маршрутам, визуальная проверка в твоём Qt-окне остаётся после установки.
