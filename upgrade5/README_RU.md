# META 5.0 — локальное обновление Core и Desktop

Дата: 2 ноября 2026 года. Исходная установленная версия перед этой работой — META Core 4.6.1. Обновление установлено в существующие `D:\META\Core` и `C:\Users\user\Downloads\META_1_3_Hotfix`.

Это рабочая реализация семи согласованных направлений. Публичный сервер, регистрация сторонних пользователей и размещение в интернете в эту версию не входят. Оценка «70% Claude Code» не используется: без общего набора задач такой процент нельзя подтвердить. Установка инструментов не превращает локальную модель в Claude или ChatGPT.

## Что открыть прямо сейчас

Обычный ярлык META продолжает запускать Desktop. В боковом меню появились **«Агент и проекты»**. Там четыре вкладки: **Задача, Проект, Модели, Память**. В обычном чате появились выбор модели, папка проекта, остановка и повтор ответа.

Для проверки разговора напиши в одном чате:

1. «Я люблю играть в Хойку».
2. «Расскажи про парадокс скрипт и сделай веб-сёрчинг».

В раскрывающемся блоке «Поиск и действия» должна быть тема Hearts of Iron IV и запрос `Hearts of Iron IV scripting modding syntax`. Ниже отображаются реальные источники и пометки: страница прочитана или доступна только поисковая выдержка. При смене темы, например на Python или погоду, прежняя игра не должна добавляться в новый запрос.

Если Desktop после перезапуска просит локальный пароль, введи прежний пароль в самом приложении. Сброс учётной записи не нужен. Пароль в чат отправлять не следует.

## 1. Общая архитектура

В Core создан пакет `meta5`. Он объединяет доступ к Ollama, профили моделей, историю задач, контекст разговора, поиск, память, инструменты проекта и подготовку изменений.

Обычный чат и агент используют общий механизм работы с моделью. Если чат получает явную просьбу изменить файл проекта, он передаёт её тому же исполнителю задач. Старые маршруты `/chat`, `/v1/chat/completions`, `/agent40` и существующее подтверждение `agent_pending` сохранены через совместимые обёртки.

Загрузка моделей проходит через общую очередь: одновременные задачи не должны бесконтрольно загружать несколько тяжёлых моделей в 4 ГБ видеопамяти. Старые установочные скрипты и исторические копии исходников не переписывались. Активная точка входа Core упрощена.

Основные модули: `transport.py`, `dialogue.py`, `agent.py`, `jobs.py`, `api.py`, `tools.py`.

## 2. Выбор моделей по измерениям

На этом компьютере обнаружены Intel Core i5-11400H, 16 ГБ оперативной памяти и RTX 3050 Laptop с 4 ГБ видеопамяти. Измерены уже установленные `qwen2.5:3b`, `qwen3:4b`, `qwen2.5-coder:7b`, `qwen2.5-coder:14b`. Новые веса моделей не скачивались.

Выполнялись три короткие проверки: узнать игру по слову «Хойка», назвать игру после явного уточнения контекста и написать простую функцию сложения в Python. Это проверка базовой пригодности и скорости, а не полная оценка программирования или интеллекта.

|---|---|---|---|
| qwen2.5:3b | Ошибка, 2,26 с | Верно, 3,81 с | Верно, 0,28 с |
| qwen3:4b | Ошибка, 4,63 с | Верно, 6,50 с | Верно, 0,90 с |

По этим результатам базовые профили: общение — 3b, работа с кодом — coder 7b, дополнительный тщательный режим — coder 14b. Название тщательного режима не означает гарантированного превосходства: 14b тоже ошиблась в одном тесте. Профиль изображений сохраняет установленную `qwen2.5vl:3b`; её качество этим измерением не оценивалось.

Дополнительно сравнены настоящие объяснения Paradox Script с поиском. У 3b встретились неточные формулировки; coder 7b дала более связное техническое объяснение, но полный ответ занял 77,14 с. Поэтому техническая тема Paradox Script автоматически направляется в кодовый профиль, а обычное общение остаётся на быстром. Это решение по этому примеру, не доказательство превосходства на любых вопросах. Ручной выбор модели сохраняет приоритет.

Во вкладке «Модели» можно выбрать установленные модели вручную и повторить измерения. Приложение сохраняет результаты и выбор. В обычном чате ручное имя модели имеет приоритет над автоматикой. Полные результаты находятся в `benchmark_results_full.json` и `candidate/core/meta5_models_seed.json`.

## 3. Более глубокое понимание проекта

Добавлены карта текстовых файлов, зависимости из основных файлов проекта, правила `AGENTS.md`, определения и импорты Python, базовые определения JavaScript/TypeScript и поиск упоминаний.

Агент читает диапазоны строк, видит номера строк и выбирает подходящие файлы по задаче и именам определений. Для большого файла доступна точная замена уникального фрагмента. Полная перезапись существующего файла запрещается, пока он не прочитан целиком. Это снижает риск потерять непрочитанную часть кода.

Защищены выход за каталог проекта, системные имена Windows, ссылки и junction, скрытые файлы с секретами. Рабочие зависимости, кэши, `.git` и служебные папки исключены из анализа.

Текущие пределы: до 5000 текстовых файлов; чтение одного файла до 2 МБ; до 300 строк за запрос; изменение одного файла до 256 КБ. Карта JavaScript/TypeScript основана на поиске объявлений, а не на полноценном языковом сервере. Семантический индекс с векторной базой и полный анализ всех языков здесь не заявляются.

## 4. Инструменты разработки

Агент получает общий набор инструментов: список файлов, чтение, поиск, определения, сведения о проекте, создание и точное редактирование файлов, удаление, переименование, план, Git, тесты, локальный сервер, браузер и подготовка окружения.

Для Git-проекта создаётся отдельный worktree с веткой `meta/<ID задачи>`. Для папки без Git — отдельная копия с локальным базовым коммитом. Можно просматривать статус, diff, недавние коммиты и ветки, а также создать локальный коммит подготовленных правок. Публикация и отправка коммитов не выполняются автоматически.

Установлены средства для Python unittest/pytest, Node test, npm test, TypeScript и Playwright с уже имеющимся Edge. Node и пакеты находятся в `D:\META\Tools`. Конфигурация путей — `meta5_tools.json`.

Тесты запускаются фиксированными профилями, без произвольной строки командной оболочки. Вывод ограничен; есть срок выполнения, остановка и завершение дерева процессов Windows. Для Python и Node можно отдельно разрешить загрузку зависимостей в рабочую копию. Это отдельное разрешение: обычная галочка запуска тестов не разрешает скачивание.

Браузер открывает только локальный сервер, запущенный текущей задачей. Он возвращает заголовок, HTTP-статус, текст страницы, ошибки и снимок. Такой режим позволяет проверять веб-проект, а не только генерировать HTML.

**Windows-режим выполняет код с правами пользователя. Рабочая копия, ограничения ресурсов и список команд не являются полноценной защитной песочницей.** В интерфейсе это обозначено. Нельзя давать такой запуск недоверенному проекту, рассчитывая на защиту файлов пользователя.

Предусмотрен отдельный режим Docker с отключённой сетью и ограничениями. На этом компьютере Docker и WSL отсутствуют, поэтому контейнерное исполнение здесь не проверялось и не объявляется готовым. Выбор Docker выдаёт понятную ошибку; скрытого перехода к Windows нет. Виртуализация Windows не включалась, перезагрузка не выполнялась.

## 5. Возобновляемый агентный цикл

Цикл устроен так: задача → изучение файлов → действия инструментами → проверка → итог и заявка. Перед продолжением сохраняются рабочая копия, прочитанные файлы, подготовленные изменения, план и сообщения инструментов.

Один проход ограничен числом шагов и временем. По умолчанию это 24 шага и 15 минут; API допускает до 60 шагов и часа. Пауза не удаляет прогресс. После остановки или перезапуска Core совместимую задачу можно продолжить кнопкой «Продолжить». Самостоятельный запуск прерванной задачи после перезагрузки не выполняется.

Повтор одного действия без прогресса останавливается. Некорректный ответ или тайм-аут модели сохраняет контрольную точку. Изменение кода после теста делает прежний результат устаревшим. Задача, требующая правок, не объявляется завершённой, если изменения не подготовлены.

Подготовленные создания, изменения, переименования и удаления объединяются в одну заявку в существующем `agent_pending`. Перед применением показывается diff. Проверка хешей не позволяет молча затереть файл, который изменился с начала задачи. При сбое применения выполняется восстановление уже записанных файлов; сохраняется квитанция операции.

История задач остаётся доступной. Во вкладке «История» можно освободить рабочую копию завершённой/остановленной задачи. Это отключает её дальнейшее продолжение, но сохраняет историю и готовую заявку. Предел одновременно сохранённых копий — 40; автоматического удаления незавершённой работы нет.

Синхронный шаг кодовой модели завершается в пределах своего тайм-аута: остановка задачи не всегда мгновенно прерывает уже выполняющийся запрос Ollama. Обычная потоковая генерация прерывается отдельным сигналом.

## 6. Общение и память

В обычном чате используется настоящий поток Ollama, а не показ заранее готового ответа по буквам. Есть остановка запроса и повторная генерация. Desktop сохраняет ответ перед завершающим событием, чтобы обновление окна не теряло последнюю реплику. При повторе прежний ответ архивируется в таблице версий.

Свежие сообщения сохраняются в контексте, а старые пользовательские цели могут сжиматься в помеченную выдержку. Это ограниченное извлечение текста, а не обещание бесконечного контекста или полного понимания каждого старого сообщения.

Добавлена отдельная редактируемая память фактов и предпочтений: ручное добавление, изменение, удаление и выключение автоматического сохранения явно сообщённых предпочтений. Примеры автоматического сохранения: «Запомни: …», «Я люблю …». Фразы «не запоминай» учитываются. Есть фильтр распространённых секретов; он не заменяет осторожность при работе с личной информацией.

Сводки проекта сохраняются отдельно и передаются следующей задаче как недоверенные данные. Память не может выдавать дополнительные права инструментам. Прежняя память не удалена и остаётся в старом разделе настроек; новая база находится в `meta5_state/memory.sqlite`.

## 7. Контекстный и наблюдаемый интернет-поиск

Раньше неудачный запрос или совпадение имени могло увести ответ к посторонним людям и Telegram. Теперь перед поиском выделяются тема, последняя явно указанная игра, исправления пользователя и подходящие предпочтения.

Для HOI4, CK3, EU4, EU5 и Stellaris есть явные правила распознавания названий и сленга. «Хойка» в игровом разговоре связывается с Hearts of Iron IV. Запрос про Paradox Script дополняется игрой и терминологией скриптов/моддинга. Уточнение «не про Хойку, а CK3» меняет выбор; новая явно указанная тема имеет приоритет над старой памятью.

Источники оцениваются по связи с игрой и темой; документация соответствующей игры получает приоритет. Посторонние социальные ссылки исключаются, если пользователь не запросил их явно. Для общего вопроса о скриптах статья Modding получает преимущество перед узким разделом GUI. При ошибке первого поиска предусмотрен дополнительный запрос к документации игры.

В интерфейс передаются поисковый запрос, найденные и исключённые источники, попытки чтения и причины ошибок. HTTP 403 не называется успешным чтением. Поисковые выдержки остаются доступными, даже если страницу открыть нельзя. Гиперссылки, придуманные моделью и отсутствующие в полученных источниках, фильтруются при потоковой выдаче; ссылки внутри примеров кода сохраняются.

Это не универсальное распознавание любого сленга. Неоднозначное слово вне известного контекста по-прежнему может потребовать уточнения. Поиск зависит от доступности внешних сайтов и бесплатных провайдеров; гарантировать отсутствие отказов и блокировок нельзя. При сбое показывается причина вместо выдуманных результатов.

## Установка, повторный запуск и восстановление

На этом компьютере обновление уже применено. Повторно запускать установку для обычного использования не требуется.

Архив предназначен для этой существующей установки. Это не самостоятельный дистрибутив Windows со всеми моделями и зависимостями. Папки Core и Desktop должны уже существовать. Конфигурация локального токена, базы чатов и веса моделей в архив не включены.

Для повторной установки распакуй архив и запусти `INSTALL_META5.cmd`. Установщик проверяет исходные хеши и целостность пакета, сохраняет прежние файлы и перезапускает локальные Core/Desktop. Если исходники после снимка изменились, операция останавливается. Активная агентная задача также блокирует обновление. Пользовательские проекты установщик не заменяет.

Резервная копия этой установки: `D:\META\Core\upgrade_backups\META5_20261102_185250_019044`. Точный путь также записан в `install-last.json` рядом с установщиком. Сохрани этот файл вместе с пакетом.

Для отката запусти `ROLLBACK_META5.cmd`. Он остановит локальные процессы META, восстановит изменённые файлы и вернёт прежний Core/Desktop. Если ты успел самостоятельно изменить обновлённый файл, проверка остановит откат, чтобы сохранить твою работу. Новая память, история задач, квитанции и средства в `D:\META\Tools` при откате не стираются.

Проверка пакета без записи:

```powershell
& D:\META\Core\.venv\Scripts\python.exe .\installer.py check
```

Запуск проверок из распакованной папки:

```powershell
& D:\META\Core\.venv\Scripts\python.exe .\test_meta5.py
& D:\META\Tools\node.exe .\test_ui.cjs
```

Восстановление уже применённой файловой заявки проекта — отдельная операция, не откат версии META:

```powershell
Set-Location D:\META\Core
& .\.venv\Scripts\python.exe -m meta5.changes rollback ID_ЗАЯВКИ
```

Команда проверяет сохранённую квитанцию и откажется затирать более поздние изменения.
