# C++: рабочая памятка META Code

## Структура и toolchain
Прочитай CMakeLists.txt или проект компилятора и узнай выбранный стандарт языка.
Не смешивай флаги MSVC, GCC и Clang. Для небольшой программы достаточно исходника
и понятного способа сборки; для нескольких модулей свяжи заголовки, исходники и
цели сборки. Не добавляй платформенные вызовы, если задача требует переносимости.
Наличие текста .cpp не доказывает, что на машине есть подходящий компилятор.

## Владение и безопасность памяти
Используй RAII, контейнеры и умные указатели там, где они выражают владение. Не
возвращай ссылку или указатель на локальную переменную. Проверяй границы, длину
ввода и арифметические преобразования. Не сохраняй итератор после операции,
которая может его инвалидировать. Не смешивай разные способы выделения и
освобождения памяти. Избегай ручного new/delete без необходимости.

## Ошибки, ресурсы и параллельность
Потоки, файлы и блокировки должны освобождаться при любом пути выхода. Исключение
не должно оставлять объект в неизвестном состоянии. Для разделяемых данных нужна
синхронизация; volatile не заменяет блокировку или атомарную операцию. Не удерживай
mutex во время долгого сетевого запроса. Продумай отмену и время ожидания.
Для ввода используй понятную проверку результата, а не предполагай корректность.

## Проверки и ограничения
Запускай сборку и программу только разрешённым способом. CMake может выполнять
пользовательские команды при конфигурации и сборке. При отсутствии toolchain
отметь, что компиляция не выполнена. Проверяй пустой ввод, крайние значения,
повторную операцию и освобождение ресурсов. Предупреждения и санитайзеры полезны,
если они доступны и запуск разрешён; не выдумывай их результаты. Проверка баланса
скобок не заменяет разбор C++ компилятором.

Источник для уточнения языка: https://learn.microsoft.com/en-us/cpp/cpp/
