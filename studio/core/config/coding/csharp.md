# C#: рабочая памятка META Code

## Проект, SDK и запуск
Сначала изучи .csproj, TargetFramework, Nullable и существующие пакеты. Не меняй
целевую платформу без причины. Не считай старый csc.exe доказательством поддержки
современного SDK. Создай согласованные исходники, namespace и точку входа. Для
библиотеки не нужен Main; для приложения нужна понятная команда запуска. Если
версия SDK неизвестна, прямо укажи это, вместо заявления об успешной сборке.

## Модель данных и ошибки
Разделяй предметную логику, хранилище и UI. Используй типы, проверку аргументов и
nullable-контракты. Сериализацию и ввод данных проверяй на повреждённые значения.
Освобождай IDisposable через using. Не подставляй пользовательские строки в SQL,
пути и команды. Лови ожидаемые исключения и возвращай понятный результат, не
скрывай ошибки пустым catch. Не добавляй ключи или пароли в appsettings и примеры.

## Async, UI и отмена
Долгие операции возвращают Task и принимают CancellationToken, где это применимо.
Не вызывай .Result и Wait в UI-потоке. Состояние элементов обновляй через правильный
поток интерфейса. Различай отмену и ошибку. При закрытии окна останавливай фоновые
операции и освобождай ресурсы. Для сети задавай тайм-аут; не запускай неограниченное
число одновременных запросов и не повторяй необратимое действие вслепую.

## Сборка и тесты
XML-разбор .csproj подтверждает лишь структуру XML. Не называй его компиляцией.
dotnet build/test может выполнять цели MSBuild и восстанавливать пакеты: это
исполнение кода проекта, которое требует разрешённого запуска. Не запускай его
автоматически в произвольном скачанном проекте. Отдельно проверяй бизнес-логику,
ошибочный ввод, отмену и повтор операции; указывай, какие проверки реально прошли.

Источник для уточнения языка: https://learn.microsoft.com/en-us/dotnet/csharp/tour-of-csharp/
