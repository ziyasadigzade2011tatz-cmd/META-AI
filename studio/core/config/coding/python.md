# Python: рабочая памятка META Code

## Структура проекта и зависимости
Сначала прочитай pyproject.toml, requirements.txt и существующие импорты. Сохраняй
совместимость с выбранной версией Python. Для небольшого скрипта достаточно одного
модуля; для приложения отделяй бизнес-логику, хранение и интерфейс. Не создавай
пустые пакеты ради количества файлов. Описывай запуск и необходимые зависимости.
Не добавляй стороннюю библиотеку, если достаточно стандартной и задача не требует иной.

## Файлы, данные и безопасность
Используй pathlib.Path и явную UTF-8 для текста. Открывай ресурсы через with.
При сохранении важных данных сначала сформируй и проверь новое содержимое, затем
замени файл через временный файл в том же каталоге. Проверяй относительные пути,
ошибки доступа и повреждённый JSON. Не подставляй входные строки в SQL; используй
параметры. Не выполняй строки через eval/exec и не собирай shell-команды из ввода.
Секреты читай из окружения, не зашивай их в пример приложения.

## Async, отмена и скорость
Не выполняй блокирующее чтение сети внутри event loop. Асинхронные запросы должны
иметь тайм-аут и отмену; для блокирующего API используй ограниченное число рабочих
потоков. Отмена asyncio-задачи не останавливает автоматически функцию в отдельном
потоке: передавай сигнал отмены и проверяй его. Освобождай блокировки в finally.
Не создавай бесконечные повторы без паузы, дедлайна и сообщения об ошибке.

## Ошибки, типы и тестирование
Лови ожидаемые исключения, а не скрывай любой сбой через pass. Сообщение об ошибке
должно объяснять действие пользователя без токенов, паролей и лишнего содержимого.
Используй аннотации там, где они уточняют контракт. Добавляй unittest для основной
логики, пустого ввода, повреждённых данных и повторной операции. Сеть в модульных
тестах подменяй; не обращайся к платным API. AST-разбор подтверждает синтаксис,
но не наличие зависимостей и не правильность поведения.

Источник для уточнения языка: https://docs.python.org/3/tutorial/
